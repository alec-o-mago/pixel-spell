# AGENTS.md

Guidance for AI coding agents working on Pixel Spell.

## What this project is

Pixel Spell is a client-only pixel art editor built with Svelte 5, Vite, TypeScript, Tailwind CSS 4, shadcn-svelte, bits-ui, and Lucide icons. It supports layered sprites, frame-by-frame animation, PNG export, and portable JSON projects.

There is no backend, database, or server-side rendering. Everything runs in the browser.

## Commands

```bash
npm run dev      # Vite dev server
npm run check    # svelte-check + tsc; must pass before finishing
npm run build    # production build
npm run preview  # preview the production build
```

Use `npm run check` after any non-trivial change. Run `npm run build` before declaring work complete.

## State and reactivity

- The singleton is exported as `editor` from `editor.svelte.ts`. **Do not rename it back to `state`**: a local binding named `state` conflicts with the `$state` rune and breaks compilation.
- `editor.doc` is a `$state` proxy, so layer names, visibility, opacity, frame arrays, etc. are reactive.
- Pixel data lives in `Uint32Array` cels. Typed arrays are **not** deeply proxied, so mutating pixels will not trigger a re-render on its own. Call `editor.touch()` (increments `revision`) after changing pixel data, or increment `editor.revision` after structural changes that do not already do so.
- Any mutation that should be undoable must call `editor.pushHistory()` **before** the change. Pixel edits, layer/frame add/delete/duplicate/reorder, clear layer/frame are undoable. Selection, visibility, opacity, and renaming are not.
- `editor.revision` is the render invalidation signal. `CanvasStage`, `LayerThumb`, and `FrameThumb` read it inside `$effect`.
- Frames own one cel per layer: `layer.cels[frameIndex]`. Adding/removing frames must update every layer's `cels` array in lockstep with `doc.frames`.

## Pixel format

Pixels are packed little-endian RGBA:

```ts
(a << 24) | (b << 16) | (g << 8) | r
```

- Transparent = `0`.
- Use `packColor(hex, alpha)` and `unpackColor(value)` from `color.ts`; do not hand-roll bit shifts elsewhere.
- `compositeFrame(doc, frameIndex)` flattens visible layers into a new `Uint32Array`.
- `pixelsToImageData` writes a cel/buffer directly into `ImageData` via a `Uint32Array` view. Keep this path intact for performance.

## Drawing pipeline

`CanvasStage.svelte` owns pointer handling:

1. Convert pointer coordinates to document pixels with `pixelFromEvent` (uses the canvas `getBoundingClientRect`, not zoom math).
2. On pointer down: guard against hidden/locked layers, push history, snapshot the active cel for shape preview.
3. Freehand tools paint through `paintBrush` (applies size and X/Y symmetry).
4. Shape tools restore the backup cel on each move and redraw from the start point, so the preview is non-destructive until pointer up.
5. Fill and eyedropper are single-click operations.
6. Every pixel change calls `editor.touch()`.

When adding a tool:

1. Add its id to `ToolId` in `types.ts`.
2. Add metadata to `TOOLS` in `tools.ts` and map its shortcut.
3. Add an icon branch in `ToolIcon.svelte`.
4. Add pointer behavior in `CanvasStage.svelte`.
5. Add its options in `ToolOptions.svelte`.
6. Add a shortcut row in `ShortcutsDialog.svelte`.
7. Update the README shortcut table.

## UI conventions

- Use existing shadcn-svelte components from `$lib/components/ui/*`; do not introduce a second component library.
- Import Lucide icons from deep paths, e.g. `import Pencil from "@lucide/svelte/icons/pencil";`.
- Svelte 5 syntax only: `$props()`, `$state`, `$derived`, `$effect`, `onclick` (not `on:click`), snippets with `{#snippet}`/`{@render}`.
- Import local TS modules with `.js` extensions (`./doc.js`, `$lib/utils.js`) and `.svelte` components with their full filename.
- The visual language is a clean, modern app UI — not pixel-art chrome. Use shadcn tokens (`bg-background`, `text-muted-foreground`, `border`, `ring`, etc.) rather than hard-coded colors. The only intentionally pixel-flavored elements are the canvas checkerboard and the logo mark.
- Keep panel headers at `h-11` and icon buttons compact (`size="icon-xs"`/`icon-sm`) to preserve the layout.
- The `Slider` component requires `type="single"` (bits-ui does not infer it). Use `type="single"` for all single-value sliders.
- Tooltips on the tool strip are required; new tool buttons should follow the same `Tooltip.Root` + `Trigger` + `Content` pattern.

## Layout contract

The shell is intentionally:

```
Menu bar
├── Tool strip (left, thin, square buttons + tooltips)
├── Left panel (tool options on top, color picker/palette below)
└── Main area
    ├── Canvas (fit/zoom, grid, cursor, floating zoom pill)
    └── Bottom panel (layers vertical list + frames horizontal timeline)
```

Preserve these regions and their relative placement when making changes.

## Persistence and files

- Project format identifier: `"pixel-spell"`, version `1`.
- `serializeProject` stores cels as base64; `parseProject` validates dimensions, frame count, layer data, and palette. Invalid files return `null` and the UI alerts the user.
- PNG export uses `canvas.toDataURL`; sprite sheets place frames horizontally.
- `editor.saveToFile()` triggers a browser download and clears the dirty flag.

## Gotchas

- Vite HMR re-evaluates the state module and resets the in-memory document. This is expected during development; do not treat it as a bug.
- `setPointerCapture` is wrapped in `try/catch` so synthetic pointer events (used in automated browser checks) do not throw.
- The file input in `MenuBar.svelte` is hidden. It is opened via `File → Open project…`.
- `$effect` in `FramesPanel` drives playback with `setInterval`; it depends on `editor.playing`, `editor.doc.fps`, and `editor.doc.frames.length`. If you add playback features, keep cleanup in the effect return.
- The canvas scroll area uses `w-max` inside a centering flex container so oversized manual zoom levels remain reachable in both directions.
- Layer visibility/opacity are document-wide. Per-frame visibility would require a model change and UI work.

## Definition of done

- `npm run check` passes with zero errors/warnings.
- `npm run build` succeeds.
- Drawing, erasing, fill, shapes, eyedropper, undo/redo, layer operations, frame operations, and playback still work.
- New UI matches the existing modern shadcn aesthetic and respects the layout contract.
- Update `README.md` when user-facing behavior or shortcuts change.
